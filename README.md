## 📌 기획 배경
한국외대 학생은 학사 제도 하나를 확인하려고 여러 사이트를 오가야 합니다.
조사해 보니(2026.11.10 기준) 학교 메인 홈페이지 한 화면에서 하위 사이트 57곳으로 연결되고, 사이트맵 링크는 771개였습니다.
예를 들어 '이중전공'은 제도 소개, 신청 일정, 신청 시스템, 배정 기준이 모두 다른 곳에 흩어져 있습니다.

HUFS Quest는 학생이 겪는 두 가지 정보 문제를 한 화면에서 해결합니다.
- **이미 알고 찾는 정보** → 화면 상단의 AI 검색창에 바로 질문
- **몰라서 놓치는 정보** → 캠퍼스를 탐험하다 만나는 퀘스트가 먼저 알려줌

## 🧠 빠른 검색창: RAG 구조
<!-- 다운로드 폴더의 '빠른검색창_RAG_구조도_남색.png'를 docs/ 폴더에 넣고 연결 -->
![RAG 구조도](docs/rag-architecture.png)

1. **수집:** 학교 홈페이지의 공개 학사정보 페이지 27곳을 robots.txt를 지켜 수집
2. **임베딩:** 242개 문서 조각(표를 조건 포함 문장으로 정리한 조각 포함)으로 나누고 CLOVA Studio 임베딩 v2(1024차원)로 벡터화해 Supabase에 저장
3. **질문 정제:** `HCX-DASH-002`가 사용자 질문을 공식 학사 용어로 다듬음
4. **검색 + 생성:** 가장 가까운 문서를 찾고 `HCX-005`가 그 문서 내용만으로 답변
5. **환각 방지:** 관련 문서가 없으면 AI를 호출하지 않고 "찾지 못했다"고 안내, 근거에 없는 숫자·날짜는 자동으로 걸러 원문을 대신 표시

### 📊 정확도 테스트 (배포 사이트 대상, `npm run eval`)
| 시점 | 질문표 | 결과 |
|---|---|---|
| 예선 (11/10) | 20문항 | 학사 질문 17개 중 14개(82%) 일치, 범위 밖 3개 모두 "찾지 못했다" |
| 본선 (11/17) | 50문항 (기본·구어체·조건·혼동·영어·범위밖) | 학사 질문 **45개 중 43개(96%)** 일치, 범위 밖 **5개 모두** "찾지 못했다" |

- 다음 단계: 규칙 무시 요구·태그 삽입 요구·복합 질문 같은 **까다로운 질문 묶음**을 추가해 따로 채점합니다.
- 문서를 늘리거나 지시문을 고칠 때마다 전체를 다시 돌리고, 정답 수가 떨어지면 반영하지 않습니다.

- **Game:** Phaser 3, Vite

- **예선(기획서·프로토타입):** 학사 문서 수집·임베딩, RAG 구조 설계, 검색창 답변 프롬프트 설계, 환각 방지 로직
- **본선:** 게임 개발(Phaser 로직·UI), 맵·그래픽(Tiled·도트 에셋)

## 🚀 실행 방법
> Windows PowerShell에서는 `npm` 대신 `npm.cmd`를 쓰세요.

```bash
npm install
npm run dev        # 로컬 실행 (http://localhost:5173)
npm run collect    # 학사 페이지 수집
npm run ingest     # 임베딩 후 벡터 DB 저장
npm run eval       # 검색창 정확도 테스트
```
> CLOVA Studio, Supabase API 키가 필요합니다. `.env.example`을 참고해 `.env`를 만드세요.
