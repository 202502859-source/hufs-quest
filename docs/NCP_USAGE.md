- 담당: 신중혁

AI 내부 스키마는 title, dept, category,
startsAt, deadline의 value/evidence 객체로 구성한다.

category는 academic, scholarship, campus,
external 및 분류 보류용 빈 문자열로 제한한다.

최종 공지 초안에서는 빈 분류를 허용하지 않는다.
빈 날짜 값은 null로 변환한다.

id와 url은 AI가 생성하지 않고 사용자가 입력한
학교 공지 원문 주소를 검증하여 코드에서 확정한다.

title과 dept의 영문 값은 비워 두고 팀원이 검수 시
작성한다. checked는 AI 초안에서 생성하지 않는다.

이 방식은 기존 notice:draft 호환을 위한 설계이며,
작업지시서의 최종 공지 구조와 모델 내부 스키마를
분리한 부분은 PM 검토 대상이다.

- F01: 2026. 11. 30.(월) 17:00까지
- F02: ~12/5(금)
- F03: 1차 마감 2026.11.30.(월) 17:00,
  2차 마감 2026.12.04.(금) 18:00
- F04: 2026.11.30.(월)까지

F01은 정확한 마감 일시 추출을 기대한다.
F02~F04는 단일 마감 일시를 확정할 수 없으므로
보류하는 것을 기대한다.

### 최초 모델 비교 및 개발 중 진단

category enum 추가 전 최초 비교에서
두 모델 모두 F01의 정확한 마감일을 반환했다.

HCX-005는 F02~F04 모두 마감일을 반환했고,
HCX-007은 F03과 F04에서 마감일을 반환했다.
두 도우미 모두 최종 검증에서는 해당 날짜를 차단했다.

최초 비교 평균 실행 시간:

- HCX-005: 4.817초(CLI 실행)
- HCX-007: 3.191초(함수 실행)
- HCX-007 순수 API 응답: 약 3.186초

HCX-007 개발 중 F01 제목 검증에 두 번 실패했다.
두 번째 진단 호출에서는 제목 값과 근거가 모두
null임을 확인했다.

제목을 원문 그대로 추출하도록 지시문을 보완한 후
F01의 5개 추출 필드 및 최종 원문 검증이 통과했다.
원문 검증 조건은 완화하지 않았다.

### 최초 구현의 안전장치

- 개인정보 의심 패턴은 API 요청 전에 차단한다.
- 날짜 및 시각을 원문과 대조한다.
- 불확실한 날짜와 복수 마감은 보류한다.
- 검증 실패 시 초안을 폐기하고 정해진 사유를 출력한다.

Structured Outputs만으로 내용의 정확성이

개인정보 검사와 날짜 검증은 모든 표현을 완벽하게
탐지하지 못한다. 원문을 사람이 사전에 확인하고
최종 데이터도 팀원이 검수해야 한다.
