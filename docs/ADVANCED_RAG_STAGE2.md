## 1. 데이터 정비 결과

| 항목 | 결과 |
|---|---:|

기존 data/chunks.json은 수정하지 않았다.

기존 510개 중 506개에 주제를 분류했으며,
분류가 모호한 4개는 unknown으로 유지했다.
이는 분류 적용률이며 분류 정확도를 의미하지 않는다.

## 2. 메타데이터

- parent_id: 원본 조각 ID
- topic: 상위 주제
- subtopic: 세부 주제
- campus: 적용 캠퍼스
- cohort_min: 적용 학번 하한
- cohort_max: 적용 학번 상한
- split_label: 세분화 내용

확인되지 않은 적용 조건은 null로 유지한다.
복수 조건이 섞인 조각에 단일 학번 범위를 강제하지 않는다.

## 3. 데이터 재현 방법

저장소 루트에서 다음 명령을 실행한다.

    node scripts/prepare-rag-data.mjs

생성 파일:

    data/chunks-next-full.json

기존 파일이 존재하면 덮어쓰지 않고 종료한다.
기존 생성 파일은 보존하고 별도 작업 환경에서 재현한다.

현재 생성 및 검증 스크립트는
510개 원본과 532개 개선본을 기준으로 작성되어 있다.
향후 재수집 시 조각 수와 ID 매핑을 재검토해야 한다.

수강편람 신규 JSON은 data/manual 아래에 있으므로
향후 collect 실행 시 자동 포함될 수 있다.
기준선 비교를 마치기 전에 collect를 실행하지 않는다.

## 4. 시험용 DB 적용

아래 작업은 팀 승인 이후에만 진행한다.

1. chunks_next의 기존 데이터 및 스키마 확인
2. supabase/007_chunks_next_metadata.sql 검토
3. SQL 적용 후 신규 필드 확인
4. 개선 데이터 dry-run 검사
5. 시험용 DB 저장 및 조각 수 검증
6. Preview의 CHUNKS_RPC 설정 확인
7. 개선 데이터 평가

005_chunks_next.sql은 이미 실행한 기록이다.
다시 실행하지 않는다.

실서비스 chunks 및 기존 검색 RPC는 변경하지 않는다.

사전 검증 명령:

    node scripts/ingest.mjs --target next --advanced --dry-run

정상 예상 결과: 532개

실제 개선 데이터 저장은 팀 승인 및
--confirm-advanced 옵션이 필요하다.

이 옵션은 실제 승인 여부를 자동 확인하는 기능은 아니다.
기존 시험용 데이터의 보존 필요성도 사전에 확인한다.
실제 ingest는 기존 시험용 조각을 삭제할 수 있으므로
PM 승인 전에 실행하지 않는다.

## 5. 평가 방식

기존 평가 문항과 답변 정답 조건은 유지한다.

- original: 기존 근거 ID 기준
- advanced: 개선 데이터 근거 그룹 기준

평가 목록 확인:

    node scripts/eval.mjs --suite all --list

    node scripts/eval.mjs --suite core-1126 --dataset advanced --list

공개 핵심 평가 문항은 20개다.
숨긴 문항 10개는 PM이 최종 평가에서 별도로 관리한다.

advanced 옵션은 평가 기준만 바꾸며
실제 DB 또는 RPC 설정을 변경하지 않는다.

## 7. C18 검토 사항

기존 C18은 학번 및 단과대학에 따라
최대 수강학점이 달라질 수 있다는 일반적인 안내를 요구한다.

신규 수강편람은 2026학년도 2학기 서울캠퍼스 기준으로
최대 20학점 및 초과학점 신청, 학점이월 등의 조건을 설명한다.

적용 범위가 다르므로 신규 수강편람의 개별 조각을
기존 C18 근거와 자동으로 동일하게 취급하지 않는다.

PM의 11/26 검토 의견에 따라 C18 정답 기준을 수정한다.

- 학번 또는 단과대학별 최대 수강학점 차이를 설명하면 정답으로 인정한다.
- 초과 수강 또는 학점이월에 따른 예외를 설명해도 정답으로 인정한다.
- 수강편람이라는 단어를 필수 조건에서 제외한다.
- 모든 학생의 최대 수강학점이 동일하다는 명시적 답변은 오답 처리한다.
- 차이가 있다는 설명만 있고 적용 조건이나 예외가 없으면 근거 부족으로 처리한다.

기존 근거 ID는 유지한다.
신규 수강편람 근거 인정 범위는 원문 대조 후 별도로 검토한다.

## 9. 남은 제한 사항

- 1단계 피드백 수정 PR과의 최종 통합이 필요하다.
- Preview 주소는 팀에서 확인한 HTTPS origin을 EVAL_TRUSTED_PREVIEW_ORIGIN 환경 변수로 지정한다.
- 외부 주소 및 자동 리디렉션을 차단한다.
- 실제 배포 주소의 소유권과 DB 연결은 별도 확인한다.
- Preview의 실제 시험용 DB 연결 여부를 확인해야 한다.
- 시험용 DB SQL 적용 및 실제 ingest는 아직 실행하지 않았다.
- 메타데이터 기반 검색 우선순위는 이후 단계에서 구현한다.
- 세분화 대상 원문의 구조 및 ID 변경 시 재검토가 필요하다.
- 숨긴 문항의 개선 근거는 PM이 별도로 확인한다.
- 실제 정확도, 검색 적중률, 응답 시간은 아직 측정하지 않았다.
